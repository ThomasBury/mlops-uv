## Follow one result from the source to the label

The checkout pins a 2,091-row extract of *Valuebetennis, Tennis results and odds since 2021*, adapted under CC BY 4.0. The extract preserves the header and the selected 2021 ATP singles rows from `Main tour` and `Masters`, rounds 4–12. The provider can regenerate its export. Use the pinned copy so every learner starts from the same bytes. The archive contains settled records and cannot establish the number of scheduled matches missing from the feed. [Valuebetennis source and field definitions](https://www.valuebetennis.com/en/donnees.htm) · [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

```bash
snapshot=data/raw/valuebetennis-2021-atp.csv
grep '^369751;' "$snapshot"
```

Matteo Berrettini (`9837`) appears in source slot 1, Ergi Kirkin (`12066`) in slot 2. The winner ID is `9837` and the score `6-0 6-4` agrees with source slot 1. Using the stable string order from M0, write down `p1_id`, `p2_id` and the label you expect in Parquet.

In `_normalize_row`, the eligibility check uses the score in **source order**. Only then does it sort the ID and name pairs together. [Normalization code](../src/acebet/dataprep/historical_results.py)

```python
winner_slot = _completed_winner_slot(row["score"])
if winner_slot is None or player_ids[winner_slot] != winner_id:
    return None
(p1_id, p1_name), (p2_id, p2_name) = sorted(zip(player_ids, names))
```

The function computes `int(winner_id == p1_id)` after sorting. `"12066"` sorts before `"9837"` as text, so Kirkin is `p1` and the label is `0`. A missing or unsupported score, or disagreement between the score and recorded winner, excludes the row. Invalid identity or a row outside the pinned extract's expected scope stops the build.

The event date is January 7. The derived `available_at` is January 9 at `00:00 UTC`. The builder uses midnight UTC two calendar days after the event date as a teaching assumption because the archive supplies no publication history. M2 uses `available_at` to decide when the score can affect features.

## Rebuild twice and account for every row

The builder verifies the CSV byte hash, writes a typed Parquet table, and records the source and logical content digests. The logical digest covers the schema version and sorted normalized records, so it identifies the same history across Parquet encodings. The table carries the source attribution and license in its metadata.

```bash
work="$(mktemp -d)"
mkdir "$work/first" "$work/second"
for build in first second; do
    uv run --locked --python 3.12 python -m acebet.dataprep.historical_results \
        "$snapshot" "$work/$build/matches.parquet" > "$work/$build/preparation.json"
done
diff -u "$work/first/preparation.json" "$work/second/preparation.json"
cat "$work/first/preparation.json"
```

| Report field | Expected value |
| --- | --- |
| `input_rows` | 2,091 CSV records, excluding the header |
| `duplicate_rows` | 0 repeated copies |
| `excluded_rows` | 235 distinct results that fail the score or winner check |
| `rows` | 1,856 eligible matches |
| `source_sha256` | `ca16daa1c89b085680152dc41924cad7e2791775c23d68a083c2c0237cdf0598` |
| `content_sha256` | `2336bd8a6d63d2f88919b3956423183c5f33c1d09ad913acdc9255c82c83b71d` |

Count the CSV records independently. `read_results` checks the typed schema, verifies the source identity, and recomputes the logical digest from the written rows. Compare the two complete sets of records and check your prediction for `369751`.

```bash
uv run --locked --python 3.12 python - "$snapshot" "$work" <<'PY'
import csv
import json
import sys
from pathlib import Path

from acebet.dataprep.historical_results import read_results

snapshot, work = map(Path, sys.argv[1:])
report = json.loads((work / "first/preparation.json").read_text())
with snapshot.open(encoding="utf-8-sig", newline="") as stream:
    input_rows = sum(1 for _ in csv.DictReader(stream, delimiter=";"))
rows = read_results(work / "first/matches.parquet")
assert rows == read_results(work / "second/matches.parquet")
assert len(rows) == report["rows"]
assert input_rows == report["input_rows"]
assert input_rows == len(rows) + report["duplicate_rows"] + report["excluded_rows"]
match = next(row for row in rows if row.match_id == "369751")
print(match.p1_id, match.p2_id, match.label, match.available_at.isoformat())
PY
```

Expect `12066 9837 0 2021-01-09T00:00:00+00:00`.

## Inject two versions of the same match

Predict what happens if you append an identical copy of the row, then what happens if the copy has the same ID and a different score. Both scores name the same winner. Use `normalize_results` directly on a small sample in memory. Editing the pinned CSV would fail the snapshot hash check before the duplicate rule could run.

```bash
uv run --locked --python 3.12 python - "$snapshot" <<'PY'
import sys
from pathlib import Path

from acebet.dataprep.historical_results import normalize_results

header, row, *_ = Path(sys.argv[1]).read_bytes().splitlines(keepends=True)
original = normalize_results(header + row)
assert normalize_results(header + row + row) == original
print("Identical copy: one match")

changed = row.replace(b"6-0 6-4", b"6-4 6-4", 1)
assert changed != row
normalize_results(header + row + changed)
PY
```

The first check passes. The last line deliberately raises `ValueError: Conflicting duplicate for match 369751.` Find the `seen` check in the normalizer. It compares the full source row before deriving the label. Choosing the last copy silently would make the accepted source depend on input order. Pass `row` in place of `changed` in the last call and rerun the block to see the exception disappear.

Keep `first/matches.parquet` and `first/preparation.json` together as the `course-v1-m1` handoff. The report identifies the source and logical content and accounts for the exclusions. Rebuild both files from this tag with the commands above whenever you need a fresh copy. [M2](m2.md) starts from that history.
