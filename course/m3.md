## Split by the time a decision had to be made

Think of a fold as an earlier set of matches to fit on and a later window to forecast. Use the expanding windows below to compare all three forecasts on the same fixtures. Freeze each fold's fit at the cutoff for the first possible day in its validation window. An earlier event can still have an unavailable label at that cutoff. For fold 1, a match played February 27 is available on March 1 at midnight under the archive's two-day assumption. Would you let it train the model that has to be ready on February 28 at 23:59:59 UTC?

In `mature_indices`, both the event and the label's availability have to pass the boundary. The shared replay also calculates each validation match's Elo from results eligible at that match's own cutoff. Earlier validation results can therefore update Elo when they become available. The classifier and its preprocessing stay fixed within the fold. [Training code](../src/acebet/train/historical_evaluation.py)

```python
cutoff = prior_day_cutoff(start)
return np.flatnonzero(
    (frame["event_date"] < start) & (frame["available_at"] <= cutoff)
)
```

| 1 | March 1 to May 1 | 234 | 465 |
| 2 | May 1 to July 1 | 695 | 337 |
| 3 | July 1 to September 1 | 1,043 | 444 |

A player can appear in both windows because the service regularly forecasts returning players. If the deployment question were how the model handles players with no eligible history, score that group explicitly. Holding out player IDs would test generalization to unseen players and would change the population your score describes. A cold-start exercise must account for which results the Elo replay can see as well as which players are held out of the fit.

## Check what the pipeline learned and score the same matches

Prevalence gives every fixture the training share of labels equal to 1. Elo uses the rating gap to give each fixture its own probability. The untuned logistic pipeline learns from the Elo gap and surface. Its scaler learns the training gap's mean and scale. Its encoder learns the surfaces present in training and represents those surfaces with indicator columns. Each fold fits a fresh pipeline. Prediction applies the fitted transformations to validation features. [scikit-learn guidance on preprocessing and leakage](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)

```python
model = logistic_pipeline().fit(train[FEATURES], train["label"])
```

Log loss is the negative natural log of the probability assigned to the outcome that happened. A confident wrong forecast incurs a large loss. The development score averages the three fold losses equally. This gives each validation window equal weight even though the windows have different match counts.

The script below uses the exported IDs to check the split and recover its scores. It computes the losses directly from the probabilities. Before running it, predict whether a scaler fitted before the split would learn the same first-fold mean.

```bash
uv run --locked --python 3.12 python - "$results" "$work/comparison" <<'PY'
import hashlib
import json
import sys
from math import isclose, log
from pathlib import Path
from statistics import mean

import pandas as pd

from acebet.dataprep.historical_results import content_sha256, read_results
from acebet.train.historical_evaluation import (
    FEATURES, development_results, logistic_pipeline, replay_frame,
)

results_path, comparison = map(Path, sys.argv[1:])
history = read_results(results_path)
development = development_results(history)
report = json.loads((comparison / "comparison.json").read_text())
membership = comparison / "membership.csv"
assert content_sha256(history) == report["data_sha256"]
assert content_sha256(development) == report["development_sha256"]
assert hashlib.sha256(membership.read_bytes()).hexdigest() == report["membership_sha256"]
assignments = pd.read_csv(membership, dtype={"match_id": str})
frame = replay_frame(development).set_index("match_id")
starts = [pd.Timestamp(day, tz="UTC") for day in report["validation_starts"]]
ends = [*starts[1:], pd.Timestamp(report["final_start"], tz="UTC")]

fold_losses = []
for number, (start, end) in enumerate(zip(starts, ends), 1):
    rows = assignments[assignments["split"] == f"fold_{number}"]
    train_ids = rows.loc[rows["partition"] == "train", "match_id"]
    valid_ids = rows.loc[rows["partition"] == "validation", "match_id"]
    boundary = start - pd.Timedelta(seconds=1)
    assert not rows["match_id"].duplicated().any()
    assert set(train_ids) == {
        m.match_id for m in development
        if m.event_date < start.date() and m.available_at <= boundary
    }
    assert set(valid_ids) == {
        m.match_id for m in development if start.date() <= m.event_date < end.date()
    }
    train, valid = frame.loc[train_ids], frame.loc[valid_ids]
    model = logistic_pipeline().fit(train[FEATURES], train["label"])
    fitted = model.named_steps["features"].named_transformers_
    assert isclose(fitted["elo"].mean_[0], train["elo_gap"].mean())
    assert set(fitted["surface"].categories_[0]) == set(train["surface"])
    probabilities = {
        "prevalence": [train["label"].mean()] * len(valid),
        "elo": valid["elo"],
        "logistic_default": model.predict_proba(valid[FEATURES])[:, 1],
    }
    losses = {
        name: mean(-log(p if label else 1 - p) for label, p in zip(valid["label"], values))
        for name, values in probabilities.items()
    }
    for name, loss in losses.items():
        assert isclose(loss, report["fold_log_loss"][number - 1][name])
    fold_losses.append(losses)
    print(number, len(train), len(valid), round(fitted["elo"].mean_[0], 3))

for name in probabilities:
    assert isclose(mean(loss[name] for loss in fold_losses), report["mean_log_loss"][name])
print("All development gaps (including the fold 1 validation window):",
      round(frame["elo_gap"].mean(), 3))
PY
```

The first-fold scaler mean is about `2.694`. Fit the pipeline on `frame` instead of `train` in your scratch copy and rerun. The assertion should fail because the scaler now sees the whole development pool and learns a mean of about `4.152`. Restore the fold-specific fit before interpreting the comparison.

| Forecast | Mean development log loss |
| --- | ---: |
| Training prevalence | 0.69381 |
| As-of Elo | 0.67036 |
| Untuned logistic regression | 0.68092 |

Elo leads on these development folds. The JSON also reports the deliberately leaky Elo from the replay exercise. That diagnostic uses the match's own winner to update its rating and would be unavailable when forecasting.
